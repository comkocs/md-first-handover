# md-first-handover

**已经在跑的项目，怎么把它的记忆交给一扇新窗。**

配套 [md-first](https://github.com/comkocs/md-first) 使用，但**两者给的人不一样**：

| | 给谁 |
|---|---|
| [md-first](https://github.com/comkocs/md-first) | **新项目**。从零开一个，按规模挑一份 md |
| **本仓** | **已经在跑的项目**，而且你手上已经有一份给 AI 看的记忆（`CLAUDE.md`、`AGENTS.md`、`.cursorrules`、自己攒的章程或笔记） |

> 已有项目**不要**去用 md-first 那四份。那四份会让 AI 在你项目根建
> `宪法.md` / `项目.md` / `DECISIONS.md`——你已经有一份规矩了，再来一份就是**两份真源**：
> AI 没有优先级可依，会自己挑一份、或者把两份揉在一起，**而且不报错**。

## 两条路，挑一条

| | 你想要的 | 走哪份 |
|---|---|---|
| **完整接手** | 把老项目的记忆交给一扇新窗，顺带看看这套东西有没有能补给你的 | [`1-导出记忆.md`](1-导出记忆.md) → [`2-导入与接手.md`](2-导入与接手.md) |
| **纯净版** | 我那套挺好，不用你的方法论。**只想要一个台账工具** | [`3-只装工单台.md`](3-只装工单台.md) |

**纯净版不读前两份**，不导出、不导入、不做兼容检查、不问你要不要合并架构——
装完你的项目一个文件都没变。

> ★但工单台**是有主张的**，不是中立记事本：建单时有四样必填、
> 交板时要给验证命令和原样输出。接受不了就别装——
> 与其装了天天想绕过去，不如不装。**被绕过的流程比没有流程更坏**，
> 因为台面上还写着它在跑。详见 [`3-只装工单台.md`](3-只装工单台.md)。

## 核心：不往你的老项目里塞东西

这套东西的方向是**反的**——不是把方法文档放进你的老窗口，而是：

```
老窗口  ──导出──>  记忆导出.md  ──导入──>  新窗口（读本仓的 md）
（只读，只新建一个文件）                （手上只有导出件，碰不到你的项目）
```

**你的老项目一个文件都不动。** 这不是靠 AI 自觉，是**结构上做不到**——
新窗口手上根本没有你的项目目录。

## 两步

### 第一步：在老窗口里导出

打开你现在那扇已经熟悉项目的窗，贴这一句：

```
打开 https://github.com/comkocs/md-first-handover 下载到本地，读 1-导出记忆.md，
按它的模板把本项目的记忆导出成 记忆导出.md。
只新建这一个文件，不许改动任何现有文件。
```

详见 [`1-导出记忆.md`](1-导出记忆.md)。

### 第二步：开一扇新窗导入

**新开一扇窗**（别接你的老项目目录），把 `记忆导出.md` 给它，贴这一句：

```
读 2-导入与接手.md，再读 记忆导出.md。
按它说的先做兼容检查、再给建议，这一轮不要改任何文件。
```

它会做兼容检查、给开窗建议，然后**只问你两句话**：

1. **装不装工单台？** 三条信号中两条才值得装，不装也能跑。
2. **要不要合并成这套工作架构？** 三个答案都是对的：
   全合并 / 只补你缺的那几条 / **什么都不改**。

★而且"同意"只是同意开始，不是一次批准到底：真动手时它得先把
「共几步、每步动哪个文件」列给你，**一步一停**等你点头。

详见 [`2-导入与接手.md`](2-导入与接手.md)。

---

## 正确答案常常是「什么都不改」

一个成熟的老项目接手这套东西，大概率**不该改任何东西**——
它自己那套往往比这套还细：统一复检、派发纪律、留痕制度可能一样不缺。

所以流程必须能得出「**我没有可补的**」这个结论，
而不是硬凑几条建议来显得这趟没白来。
[`2-导入与接手.md`](2-导入与接手.md) 的征询二把「什么都不改」列为三个正确答案之一，
就是为这件事。

## 为什么导出要卡字数

记忆文件分两类，体量差着一到两个数量级：

| | 特征 | 典型体量 |
|---|---|---|
| **规矩类** | 改的时候回原处修改（章程、格式约定） | 几千字 |
| **流水类** | 按时间往下追加（收工播报、卡点、决定记录） | 可以长到规矩类的几十倍 |

整套载入新窗口会耗尽上下文，而且耗尽的是**沟通那一侧**——
它会开始丢弃你最早说的话，还不给任何提示。

所以导出件卡在 6000 字以内，只带规矩类的原文 + 流水类的清单。
**导出不是备份，是交接**：要的是「下一个人接手需要知道什么」，
不是「这个项目发生过什么」。

## 仓库结构

```
1-导出记忆.md      贴进老窗口，产出一份 记忆导出.md
2-导入与接手.md    贴进新窗口，做兼容检查 + 两个征询 + 逐步确认
3-只装工单台.md    纯净版：跳过前两份，只要台账工具
LICENSE  NOTICE   Apache-2.0
```

三份都是纯 md，本仓没有代码、没有依赖。
（纯净版会让你去 md-first 仓取 `ticket-desk/`，那个要 Python 3.10+。）
